# University configuration

University identity is supplied through the same JSON keys that Flutter accepts
with `--dart-define-from-file`. Start with the committed example:

```powershell
Copy-Item config/university.example.json config/university.local.json
dart run tool/configure_university.dart
flutter run --dart-define-from-file=config/university.local.json
```

Firebase is optional. To enable Analytics and FCM, copy and fill its separate
public configuration, then pass both files:

```powershell
Copy-Item config/firebase.example.json config/firebase.local.json
flutter run `
  --dart-define-from-file=config/university.local.json `
  --dart-define-from-file=config/firebase.local.json
```

When `FIREBASE_ENABLED` is false, startup skips Firebase and the related
Analytics, routing observer, permissions, and FCM integrations stay disabled.
Enabling it with incomplete identifiers fails fast with the missing key.
An iOS deployment must additionally enable the Push Notifications capability
and provision APNs in its own Apple/Firebase projects; these signing
entitlements are intentionally not generated by the repository.

The generator validates all fields before it writes anything. Unknown keys,
missing values, unsafe native-build syntax, non-HTTPS university URLs, invalid
email addresses, and malformed host names or deep-link schemes are rejected.

The same tenant file also configures the custom lesson editor. Use
`LESSON_BELL_SLOTS` for comma-separated `HH:mm-HH:mm` ranges,
`LESSON_COLOR_VALUES` for ARGB hexadecimal colors, and
`LESSON_REMINDER_LEAD_MINUTES` for comma-separated positive minute values.
These fields are optional for existing deployments; the committed example
shows the defaults.

Set `APP_COMMUNITY_CHAT_URL` to an HTTPS community destination when the app
should show the Telegram/chat card in Tools. Omit it to hide that card.

Set `APP_COMMUNITY_FORUM_URL` to the HTTPS Discourse/forum base URL. It is
used for forum API calls and user avatars.

Set `APP_CALENDAR_EVENT_URL` to the absolute HTTPS or custom-scheme URL that
calendar events should open. Omit it when exported events should not contain a
link.

When `nfc_pass` is enabled, set the five `APP_NFC_PASS_*_URL` endpoints and
`APP_NFC_PASS_REDIRECT_URLS` to the university's own provider. The capability
uses a documented OAuth redirect plus three gRPC-Web endpoints; it must stay
disabled when the institution has no compatible provider.

Set `APP_ALLOWED_EMAIL_DOMAINS` to comma-separated lowercase university email
domains to restrict password, code, registration, and reset flows. Omit it to
keep the default deployment policy.

Set `APP_ENABLED_CAPABILITIES` to a comma-separated subset of
`campus_map`, `nfc_pass`, and `virtual_tour`. This keeps institution-specific
screens out of another university's Services hub until its data source exists.

External services in the Services hub are configured in Supabase for the
organization identified by `APP_ORGANIZATION_ID`. See
[`service-catalog.md`](service-catalog.md) for the schema and supported icon
keys; no university URLs need to be hardcoded in Flutter.

It creates three local, human-readable files:

- `android/tenant.properties`
- `ios/Flutter/Tenant.xcconfig`
- `web/university-config.json`

They contain public deployment metadata only. The tool deliberately does not
change Android namespaces, Apple bundle identifiers, signing settings,
entitlements, Firebase files, or credentials. Gradle consumes the Android file,
Xcode consumes the iOS file, and the web bootstrap uses the web file for its
document metadata. They are not a replacement for Firebase project
provisioning.

Use check mode in local validation or CI after generation:

```powershell
dart run tool/configure_university.dart --check
```

The command exits with status `1` and lists every missing or stale output. It
does not modify files in check mode. To use a different source or project root:

```powershell
dart run tool/configure_university.dart `
  --config config/university.example.json `
  --root C:\path\to\university-app
```

Generated platform files and `config/university.local.json` are ignored because
they represent a developer's selected tenant. Review the generated text before
connecting it to a release build.

The release workflows read the same JSON from the repository variable
`UNIVERSITY_CONFIG_JSON`, validate it with this generator, and pass it to
Flutter as a Dart define file. Firebase identifiers come from the separate
`FIREBASE_CONFIG_JSON` variable. Never point a release workflow at the example
university configuration.

## Automated beta releases

Every successful `CI` run caused by a push to `master` starts the beta release
workflow. It creates a Shorebird Android release, uploads the signed APK, AAB,
mapping file, native symbols, and checksums as workflow artifacts, attests their
provenance, and publishes them in a GitHub prerelease. A manual dispatch uses
the same fail-closed path.

The `beta` GitHub environment accepts protected branches only. Configure
`UNIVERSITY_CONFIG_JSON`, `FIREBASE_CONFIG_JSON`, and `SUPABASE_URL` as
repository variables. Configure `SUPABASE_PUBLISHABLE_KEY`, `SHOREBIRD_TOKEN`,
`NFC_MODULE_DEPLOY_KEY`, `ANDROID_KEYSTORE_BASE64`,
`ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, and `ANDROID_KEY_PASSWORD`
as repository secrets. The signing values must identify the same long-lived
Android key for every beta so installed builds remain upgradeable.
