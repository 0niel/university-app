# Политика безопасности

## Поддерживаемые версии

Исправления безопасности готовятся для текущей ветки разработки. Отдельного
гарантированного графика поддержки старых опубликованных версий пока нет.

## Как сообщить об уязвимости

Не создавайте публичный issue, discussion или pull request с деталями
неисправленной уязвимости.

1. Откройте вкладку **Security** этого репозитория.
2. Если доступна кнопка **Report a vulnerability**, создайте приватный отчёт
   через GitHub Private Vulnerability Reporting.
3. Если приватные отчёты не включены, используйте приватный канал связи с
   сопровождающими, указанный на вкладке **Security**. Если такого канала нет,
   создайте публичный issue без технических деталей только с просьбой сообщить
   способ приватной связи.

В отчёте укажите затронутую версию/commit, компонент, предусловия, шаги
воспроизведения, ожидаемое влияние и безопасный proof of concept. Не отправляйте
реальные токены, Telegram session string, персональные данные студентов или
дампы production-базы — замените их минимальными тестовыми данными.

Сопровождающие подтвердят получение через выбранный приватный канал, проверят
влияние и согласуют публикацию исправления. Срок зависит от сложности и риска;
не раскрывайте детали публично до согласованного момента.

## Область ответственности

Полезно сообщать о проблемах в Flutter-клиенте, Supabase RLS/RPC/Edge Functions,
content worker, обработке deep links, аутентификации, tenant isolation,
зависимостях и CI/CD. Ошибки конфигурации стороннего университетского сервиса
следует сначала проверять у его владельца, если они не вызваны кодом этого
проекта.
